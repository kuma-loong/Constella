# Profile 看板：参考调研与新方向

2026-09-06。本文记录已确认的设计方向；正式页面按后续确认的 Demo 和后端口径落地。沿用英文界面、实验室用户定位、账号设置二级入口，以及已取消回顾的决定。

## 当前稿的主要问题

这是对当前设计的判断，不是外部研究结论：

- 主视觉由巨大统计数字、两条平滑曲线和分隔面板组成，换一组标签就能成为收入、健康或网站流量看板，缺少 GPU 工作的特征。
- 7 个每日示例值经过平滑插值形成曲线，小时分布又来自模拟函数。曲线外形没有体现任务的开始、结束、并行与中断，继续修改粗细、底色不能解决这个问题。
- 「GPU hours → Busiest hours → Most-used GPU」停留在汇总层，具体工作在下方列表才出现。图形与任务没有形成清晰的主从关系。
- 多次加载都从左到右描绘曲线属于呈现效果；对寻找任务、理解并发和查看历史帮助有限。

## 参考与可借鉴之处

调研范围包括公开产品页、官方帮助文档、官方演示及可公开操作的案例。Rize 官网截图和 Linear 官网演示代表公开展示，并非对登录后所有功能的实测。下表中的借鉴建议是针对 Constella 的设计推导。

| 参考 | 已核实的内容 | 对 Constella 的启发 |
| --- | --- | --- |
| [Strava Training Log](https://support.strava.com/en-us/articles/15402077-training-log) | 按周查看活动；每个活动由独立图形表示，交互可查看当天表现；支持时间/距离等维度和活动筛选。 | 让计算记录成为主视觉，每个时间范围都能回到相关任务。借鉴活动组织，不照搬运动圆点。 |
| [Rize](https://www.rize.io/) | 官网产品图以时间线呈现记录，同时展示任务、项目和汇总；同屏能看到时间花在哪里。 | 时间轴上的长短、间断与并行本身就有视觉辨识度；以一周活动和一天任务展开组织个人页。 |
| [Linear Insights](https://linear.app/insights) / [Dashboards](https://linear.app/docs/dashboards) | 图表与表格并用，可从数据点进入底层 issue 的过滤视图；官网提供动效演示。 | 图表作为工作入口。选择日期或设备后，相关任务随之更新，保留上下文。 |
| [Linear 的看板设计经验](https://linear.app/now/dashboards-best-practices) | 强调明确用途、匹配受众、提供比较上下文；日常使用的看板应更紧凑。 | 实验室个人页重在日常查看和继续工作，大数字不应挤掉任务。 |
| [Apple 图表交互演示](https://developer.apple.com/videos/play/wwdc2023/10037/) | 4:22 起介绍选择与详细信息；7:49 起介绍可滚动时间窗口、日期对齐。 | 动效围绕用户直接操作，坐标和选择保持连续；细节在需要时出现。这里只参考行为，不建议引入其原生框架。 |
| [The Pudding：Dicing an Onion](https://pudding.cool/2025/08/onions/) | 可改变切割参数、切换展开状态，并查看图形及均匀程度的变化。 | 同一批对象随操作展开，变化有含义。可用于「一天活动 → 任务轨道」的展开；不把长篇滚动叙事移入日常控制台。 |
| [Weights & Biases：运行对比](https://docs.wandb.ai/models/runs/compare-runs) | 固定重要运行、指定对比基线，在表格和图中保留对应关系。 | 任务身份和上下文必须稳定；选中的任务应在详情和分析页中持续对应。任务比较可后续考虑，不为视觉效果增加首期范围。 |

## 推荐方向：以计算活动为中心的个人工作页

页面用 **Your activity** 做标题，不再使用宣传式副标题。顶部是个人身份、周期与 Account settings；运行中任务有直接入口。

### 1. 汇总是一条紧凑数据带

GPU hours、Time with active jobs、Active days，最多三个指标。主要值约 32–40 px，单位贴近数字。GPU hours 可有上一等长周期的绝对差值，其他指标不强加趋势箭头。

Most-used GPU 移到右侧设备分布中，避免上下重复。身份与账号数量放在标题区，不占统计面板。

### 2. 主视觉是 Weekly activity

桌面主区域约占可用宽度的 70%，由横向 00–24 h 时间轴和纵向 7 个日期组成。

- 每一行是一日，有色时间段表示该时段存在本人 GPU 活动，长度表示持续时间。
- 并行 GPU 数通过有限的色阶区分，图例明确 1、2–3、4+ GPUs。颜色不同时承担任务类型或状态。
- 空白表示没有本人已归属的观测记录，不保证设备空闲。现有记录不能恢复精确采集缺口，因此不绘制推测的缺失区间。跨午夜活动在日界线切开。
- 这是按日的活动聚合。一个色段可能对应多个任务，点击后展开该日的具体任务轨道，不能把聚合片段冒充单个任务。
- 右侧对齐当天 GPU hours；用户同时能读「什么时候使用」和「用了多少」。
- 横轴每小时设短刻度、桌面每 2 小时标注；每天共享同一坐标，不把每行各自拉伸。
- 7/30 天窗口由用户切换；30 天以更紧凑但可选择的日期行呈现，选中日再展开详情，不能改成没有时间语义的装饰格子。

主图底部仅保留 Concurrent GPUs 图例和 **Busiest hours** 三小时高峰文字摘要。根据后续确认，取消逐时色带、括线和额外分布图。

### 3. 右侧是 Your GPUs

使用紧凑的对齐列表：GPU 型号、GPU hours、占比。第一名强调，其余保持中性，不添加环图或没有目标含义的进度圈。

选择某个型号时，主图与历史任务同时过滤，出现清晰的可清除标签；顶部周期总量保留，选中范围的总量显示在过滤条中，避免用户误读数字变化。通过图例和文字维持「当前过滤范围」一致。

### 4. Recent jobs 与主图形成闭环

下半区保留紧凑任务列表，运行中置顶且不被过去日期隐藏。选中某天展开的任务轨道与对应列表共享任务身份；点击任务打开已有方向的详情抽屉，再进入 Jobs 分析。完整命令和 PID 等仍在需要定位任务的位置保留，不把底层聚合算法写到页面上。

任务历史曲线仍属于实际设备时间序列，只在详情中展示。需要同时提醒：共享 GPU 的指标可能包含其他任务。没有真实采集支持时，不生成漂亮但虚构的历史曲线。

## 动效设计

以下时长为本方案建议值，不是对参考网站实现参数的测量。

| 操作 | 动效与反馈 |
| --- | --- |
| 选择一天 | 该日期行在约 220 ms 内展开为任务轨道，其他日期保持位置可追踪；右侧显示该日摘要。 |
| 悬停/触摸时间段 | 显示具体时间与 GPU 数，相关任务强调；只改变强调状态，不让整张图缩放。 |
| 按 GPU 型号过滤 | 非匹配片段先弱化，匹配任务列表随后更新；保留时间轴位置及当前选择。 |
| 前后切换周期 | 日期窗口做短距离位移，仍在两个窗口中的日期保持可追踪；日界线不跳动。 |
| 打开任务详情 | 来源行维持选中，抽屉约 200 ms 展开；关闭返回原位置。 |
| 自动刷新 | 更新改变的时间段和数值；正在查看的内容不被无提示重排。 |

首页静止状态就应完整且有辨识度。无需入场画线、全屏数字滚动、粒子、3D、自动播放或回顾。尊重减少动态效果设置。

## 视觉与移动端

- 延续 Geist / Geist Mono、方形数据面与既有控件圆角，保持 Constella 的应用一致性。
- 中性色构成页面，钴蓝表达 GPU 活动，绿色仅用于运行状态。色阶属于数量编码，不用于装饰。
- 移除 Your rhythm / Your hardware 等重复眉题，避免把普通统计写成宣传标题。
- 主图约 280–340 px 高，行与数字共用严格对齐关系；面板之间以间距和必要分隔线组织。
- 手机使用日期选择 + 当天轨道，支持前后一天切换；提供紧凑的一周摘要。将桌面七行二十四小时缩小到手机会损害可读性，因此改用专门的窄屏组织方式。

## 数据与分期边界

现有任务开始/最后观测时间与 GPU 关联能支撑第一阶段的观测时间段。精确中断与逐时并行情况需确认连续观测覆盖；若只有首末时间，图与说明必须标作记录范围，不承诺中间持续活跃。

第一版保留 7/30 天切换，并交付活动概览、日展开、设备筛选、Recent jobs 联动和账号设置入口。高峰仅显示基于记录区间的文字估计。不恢复回顾，不新增效率评分和算力消耗榜。

可选的另一方向是以 Running jobs / Recent jobs 为绝对主角、统计仅作侧栏的紧凑工作页；它操作效率更高，个人记录的视觉特征较弱。结合用户同时希望个人统计有吸引力，本次推荐 Weekly activity 主图方案。
