# 统计结果缓存

排行榜、节点历史和个人页共用一个进程内 `ResultCache`。缓存保存 JSON 字节，总容量 32 MiB，最多 128 项，按最近使用顺序淘汰。个人页原来的 16 MiB 原始记录缓存已移除。缓存不落盘，服务重启后按需重建。

## 命中和过期

1. 请求先经过身份和权限检查，再构造缓存键。
2. 使用单调时钟判断过期。有效期内直接命中，读取不会延长有效期。
3. 无缓存或已到期时，第一个请求计算；同键的其他请求等待同一任务。
4. SQL、聚合、JSON 序列化全部成功后开始固定 60 秒有效期。失败结果不缓存，下次请求可以重试。
5. 不返回过期结果，也不使用定时刷新或后台预计算。普通刷新遵守相同的 60 秒规则。
6. 新结果写入前清理过期项，再按最近使用顺序淘汰，直到符合容量和项数限制。单项超过 32 MiB 时仍返回结果，但不保留。

同一时间最多容纳 16 个不同键的未完成任务；同键等待者共用任务。队列已满时返回 503。客户端取消等待不会取消共享计算。历史 SQL 及个人聚合继续在线程中执行，沿用各自两个工作槽。

容量按实际保留的 JSON 字节计数，包括缓存中的个人任务索引；32 MiB 不等于整个进程的 RSS 上限。JSON 解码、SQL 行和重算中的中间对象另占临时内存。

## 缓存键和归属变化

| 内容 | 缓存键 | 缓存内容 |
| --- | --- | --- |
| 排行榜 | 时间范围、绑定映射指纹 | 完整接口响应，包括用户榜、任务榜及异常统计 |
| 节点历史 | 节点 ID、时间范围 | 完整曲线、热力图及元数据 |
| 个人页 | 数据库路径、用户 ID、周期、上海日期、绑定映射指纹、所选日期、型号、规范化搜索词 | 已计算的统计、时间线、型号分布及任务索引 |

绑定映射包含所有历史绑定及用户显示名，按请求读取并生成指纹。绑定、解绑、转移或显示名变化后使用新键，已有缓存不会命中旧归属。计算使用生成该指纹时读取的同一份映射。旧键的字节随后按过期或容量淘汰回收。

个人页的上海日期进入键，跨午夜立即重新生成周期。时间范围沿用原有含义：排行榜为滚动时间窗，个人页为包含今天的最近 7／30 个自然日。缓存保留真实的 `generated_at` 和 `as_of`，不在命中时伪装成刚计算。

## 个人页实时状态和分页

个人缓存不保留原始 `Usage`／数据库行，也不缓存实时运行状态。冷查询完成统计、时间线和任务分组后，将聚合结果及任务索引序列化保存。

每次请求命中后解码这份结果，对实时节点快照建立一次 PID／启动时间索引，再更新任务状态、排序、状态筛选和分页。日期、型号及搜索改变时使用各自的聚合缓存；仅改变状态、页大小或分页游标时复用已有聚合。新鲜快照缺失、采样失败或进程可见性不足时继续显示未知。

游标仍绑定统计版本、筛选条件和当前任务顺序。缓存重建或实时状态变化导致顺序变化时，沿用 409 提示重新加载。用户之间的统计严格按用户 ID 隔离，权限检查在缓存查找之前完成。

## 效果验证（2026-11-06）

使用生产数据库的独立 SQLite 快照，运行本机 FastAPI TestClient 完整请求。两组读取相同数据、固定统计时刻：关闭缓存各 3 次取中位数；首次填充一次；命中各 10 次取中位数。对每次响应正文逐字节比较，所有结果一致。节点为 8 卡节点，个人页为 yangliangxing 的已有历史。

回归测试覆盖固定到期且命中不续期、计算完成后才开始计时、同键请求合并、等待者取消、失败重试、容量／项数淘汰、超大项不保留、身份隔离、绑定及显示名变化、实时运行状态和既有分页语义。


## 节点页面反复切换的浏览器缓存修复（2026-11-06）

服务端缓存只避免 SQL 与聚合，命中后仍要传输完整响应。原前端只有当前响应的一个槽位，点击时间范围时还会清空响应和键；因此 `24h → 7d → 24h` 每次都重新请求。`7d` 还会请求完整 `24h` 响应来取其中的热力图，而不是只取热力图数据。热力图显示最近 12 小时，沿用 24 小时数据源。

已在隔离的真实数据库快照、同版后端和浏览器中复现：8 卡节点的 `24h`、`7d` 响应分别约 1.09、1.17 MB；全部服务端命中时，服务端响应头准备耗时约 0.3–2.3 ms。在浏览器设定的 10 Mbps 下行、80 ms 延迟条件下，重复切回 `24h` 仍需约 1.06 秒，重复切回 `7d` 需约 1.96 秒。资源时序显示，主要时间用于重复传输响应；曲线与热力图的共同等待会放大该问题，但并不是缓存命中后仍慢的完整解释。

前端现在按节点和范围保留最多 8 份已解码响应，使用最近使用顺序淘汰。有效期不超过请求开始或响应 `generated_at` 起的 60 秒，取较早的边界，命中不续期，避免再次缓存一个已经较旧的服务端结果而将数据年龄延长到两分钟。切换日期范围复用独立的 24 小时热力图结果；曲线、热力图各自完成后显示，成功部分不等待失败或未完成部分。手动刷新和连接恢复跳过浏览器缓存，继续遵守服务端的 60 秒规则。取消的请求不写缓存，销毁页面控制器时清空缓存。

修复后同一快照、同一网络设置中，已访问范围之间的切换没有发出新的节点历史请求：`24h` 约 0.12 秒、`7d` 约 0.10 秒完成显示，剩余时间包括浏览器 DOM、绘图与测试等待。首次未访问范围仍需请求；浏览器侧结果过期或被淘汰后也会重新请求。

这些网络数值来自可控复现，不是用户浏览器在 Cloudflare Tunnel / Access 链路上的抓包结果。修复消除了反复切换时的整次远程请求，未调整 Tunnel 或 Access 配置。原始浏览器记录位于工作区 `run/preview-node-switch/before.json` 和 `after.json`；观察缓存命中的响应头仅存在于隔离预览包装器，未改动生产服务。
